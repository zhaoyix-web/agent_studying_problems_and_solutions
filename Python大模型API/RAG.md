# RAG的相关学习
## 1.RAG到底是什么  
当前主流大模型有知识停留在预训练截止日期（时效性不足）、出现幻觉（生成虚假矛盾信息）、黑盒不可解释、输出逻辑无法回溯、无自主反馈闭环（重复犯错）等问题，
为了解决这些问题，我们会给大模型一个知识库，每次回答前大模型会提前在知识库里面寻找，这个技术就是RAG(检索增强生成)

普通RAG和AGENT RAG的区别是什么：  
普通RAG会先检索文档，直接丢给大模型回答，固定流水线，不会思考与迭代；  
AGENT RAG会把检索、工具调用、思考、多轮检索、修正步骤交给智能代理自主决策，动态调整流程

### 1.如何清洗：  
纯文本（txt、Markdown、CSV）：直接读取文件内容，通常不需要特殊的解析器。
PDF: 使用工具如 PyPDF2、pdfminer 或 AI 服务可以直接提取文字,这些工具可以理解页面结构、字体和段落。OCR 引擎（如 Tesseract、AI 服务）会分析图片中的形状，将其识别为文字。
word:使用 python-docx 等库，它们可以解析 Word 文件的 XML 结构并提取文本和样式信息。
HTML:使用使用网页抓取工具

### 2.如何分块
LLM处理长文本的能力有限，将长文本切成更小的文本块（Chunk）可以更精确地定位相关信息
目前主要的分块：  
固定长度分块，按固定字符数/token数拆分，不考虑内容逻辑
语义分块，基于文本语义关联性拆分，确保每块内容逻辑完整
段落分块，以文档自带段落为单位拆分，尊重原文结构
标题层级分块，按照文档标题级拆分，形成“大块包含小块”的层级结构
句子分块，以单个的句子为单位拆分，每块仅包含一句完整内容
混合分块，结合多种分块方法，根据文档不同部分的结构灵活拆分

### 3.文本嵌入（Embedding）
利用 Embedding 模型（一种预训练的神经网络），将每一个文本块转换成一个高维的数值向量。这个向量能捕捉到该文本块的语义信息。

### 4.向量存储 （Vector Storage）
将这些生成的向量（Embedding）存储在专门的数据库中，即向量数据库。同时，会将对应的原始文本块（Chunk）存储在关系型或文档数据库中，并与向量建立关联，以便在检索时可以快速找到原文本。

### 5.关键词检索 （Keyword Retrieval）
原理： 基于精确匹配。系统会在文档中查找是否包含用户查询中出现的具体词。它通常依赖于倒排索引（Inverted Index），这种索引结构记录了每个关键词出现在哪些文档中。

### 6.密集向量检索 （Dense Vector Retrieval）
也被称为语义检索（Semantic Retrieval）或 Embedding 检索。这是现代 RAG 系统的核心基石，它不仅寻找相同的词，更寻找相似的“意思”。原理： 基于语义匹配。它利用文本嵌入模型（Embedding Model）将文本（查询和文档块）转换成高维空间中的数字向量。在这个向量空间中，含义相近的文本会被映射到彼此靠近的位置。

### 7.混合检索 （Hybrid Retrieval）
将上述两种方式结合起来，旨在吸取两者的优点，克服各自的缺点。
结果融合 （Reranking/Fusion）： 两路检索会各自返回一个带有得分的文档列表。关键的一步是使用融合算法（如 RRF - Reciprocal Rank Fusion）将这两个列表合并，并重新对文档进行打分和排序（Reranking）。重排序模型通常是一个比嵌入模型更复杂的模型，它能根据查询和文档的全面内容，更精准地评估两者的相关性，从而选出最相关的文档供 LLM 生成。

## 3.召回率
“召回率”是衡量检索系统表现好坏的一个核心度量标准，召回率越高表示系统越完整

如何提升召回率：
### 1.优化数据分块
分块太碎语义不完整、太长噪声多
**增加重叠度**
**父子索引**

### 2.混合检索
单纯的向量检索（Vector Search）擅长语义，但对专有名词、缩写、产品型号非常不敏感。将向量检索和传统的关键词检索结合

### 3.查询转换与扩展
用户的提问往往是模糊的，直接转化成向量的效果往往不好
**查询重写（Query Rewriting）**：让 LLM 先把用户的“口语”翻译成“书面语”或更详细的描述。
**多查询并行（Multi-Query）**：让 LLM 针对同一个问题生成 3-5 个意思相近的不同表达，并行检索，取结果的并集。这能极大覆盖不同的词汇空间。

### 4.检索内容重排序
有了重排序，你就有了一个逻辑缜密的助手，他会帮你把这堆书翻一遍，把最精准的那一页呈现在你面前。
